# Cleaner для macOS — дизайн базовой версии

Дата: 2026-08-19

## Задача

Нативное macOS-приложение для чистки мусора разработчика: минималистичное окно
со списком категорий, галочками и одной кнопкой. Логика переносится с рабочего
bash-скрипта (`legacy/maccleaner.sh`), но пишется на Swift заново.

Главный критерий — сохранность данных. Он важнее полноты чистки: лучше не
удалить лишнюю категорию, чем удалить нужный файл.

## Границы первой версии

**Входит:** каркас проекта, сканирование, перемещение в Корзину для трёх
категорий — `DerivedData`, `DeviceSupport`, кэши пакетных менеджеров.

**Не входит:** симуляторы и runtime-образы (там `simctl` и необратимость),
безвозвратное удаление, `brew cleanup`, чистка логов, автозапуск по расписанию.

## Технические решения

| Решение | Причина |
|---|---|
| Tuist 4 (`Project.swift`) | Манифест на Swift; `tuist build/test` из терминала, значит работу можно проверять, а не декларировать |
| SwiftUI, одно окно | Формат выбран пользователем; таблица категорий в попапе меню-бара была бы тесной |
| App Sandbox **выключен** | В песочнице `~/Library/Developer` недоступен без ручного выбора каждой папки. Приложение — локальный инструмент, не для App Store |
| `FileManager.trashItem` | Родная Корзина с рабочей кнопкой «Положить обратно», вместо самодельного `mv` из скрипта |
| Swift 6, strict concurrency | Актуальный тулчейн (Swift 6.3.3, Xcode 26.6) |

## Структура

```
Cleaner/
├── Tuist.swift
├── Project.swift            # CleanerKit, Cleaner, CleanerKitTests
├── CleanerKit/Sources/      # логика, без импорта SwiftUI
├── CleanerKitTests/
├── Cleaner/Sources/         # SwiftUI-приложение
└── legacy/maccleaner.sh     # эталон при переносе логики
```

`CleanerKit` не импортирует SwiftUI; приложение не обращается к файловой системе
напрямую. Логика проверяется тестами без запуска окна — именно так в скрипте
нашлись баг разбора имён вида `iPad Pro 13-inch (M5)` и потеря последнего
элемента в парсере номеров.

## Компоненты CleanerKit

### PathGuard

Порт функции `guard()` из скрипта. Путь допускается к удалению, только если он:

1. абсолютный;
2. не символическая ссылка;
3. не содержит `..`;
4. лежит **строго внутри** одного из разрешённых корней;
5. не совпадает с самим корнем (проверка минимальной глубины);
6. не пересекается со стоп-листом ни в одну сторону — ни путь внутри
   запрещённого, ни запрещённый внутри пути.

Стоп-лист: `Documents`, `Desktop`, `Downloads`, `Mobile Documents` (iCloud),
`Photos`, `Mail`, `Messages`, `Keychains`, `.ssh`, `MobileSync` (бэкапы
устройств), `Xcode/Archives` (собранные релизы), `Xcode/UserData` (схемы,
сниппеты, брейкпоинты).

Корни и стоп-лист передаются в инициализатор, а не зашиты константами: иначе
тесты пришлось бы гонять по настоящему `~/Library` пользователя.

### Category

Описание категории: идентификатор, заголовок, корни, текст последствия
(«пересоберётся», «перекачается с устройства»). Чистые данные, не поведение.

### Scanner

Обходит корни категории на глубину 1, считает размеры параллельно через
`TaskGroup`, возвращает находки с размером и датой изменения. Только чтение,
никаких мутаций.

### Remover

Принимает выбранные находки и **заново прогоняет каждый путь через PathGuard
непосредственно перед удалением**. Проверка на этапе скана не засчитывается:
между сканом и нажатием кнопки проходят минуты, за которые путь мог измениться.

Удаление идёт через протокол `FileTrashing` (реальная реализация поверх
`FileManager.trashItem`, подставная — для тестов).

## Поток

Скан (только чтение) → выбор галочками → лист подтверждения с итоговым размером
→ перемещение в Корзину → отчёт.

Ничего не отмечено по умолчанию: выбор делает пользователь.
Безвозвратного удаления в этой версии нет вообще.

## Обработка ошибок

Сбой на одном пути не прерывает остальные: результат собирается поэлементно, в
конце показывается сводка «перемещено / не удалось». Отказ по правам (TCC)
выделяется отдельным сообщением — это не сбой, а требуемое действие
пользователя.

## Тестирование

| Что | Как |
|---|---|
| `PathGuard` | 21 проверка из `--self-test` скрипта, переписанные в XCTest, на временных корнях |
| `Remover` | Подставной `FileTrashing`: тесты ничего не удаляют по-настоящему; проверяется повторная валидация перед удалением |
| `Scanner` | Временное дерево каталогов с известными размерами |

Разработка ведётся по TDD: тест до реализации.

## Критерии готовности

1. `tuist test` проходит целиком.
2. Приложение собирается и запускается, показывает реальные размеры трёх
   категорий на машине пользователя.
3. Перемещение в Корзину работает, файлы возвращаются кнопкой «Положить
   обратно» в Finder.
4. Ни один тест не обращается к настоящему домашнему каталогу.
