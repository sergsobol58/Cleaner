# Cleaner

[In English](README.md)

Нативний застосунок для macOS, що прибирає мотлох розробника. Список категорій,
галочки, одна кнопка. Нічого не стирається назавжди — лише Кошик.

Інтерфейс має дві мови, українську та англійську, і йде за мовою системи.

## Відповідальність

**Програма видаляє файли. Відповідальність за їхню збереженість лежить на вас.**

Автор не відповідає за втрачені дані, зламані збірки, зіпсовані проєкти та
будь-яку іншу шкоду від використання цієї програми — ні пряму, ні опосередковану.
Це умова ліцензії MIT, а не фігура мовлення: програма надається «як є», без
жодних гарантій.

Запускайте її, лише якщо розумієте, що саме вона видаляє. Перед першим
прибиранням перегляньте список і прочитайте, чим обернеться кожна категорія, —
підписи в інтерфейсі саме для цього й написані. Вкладка «Симулятори» видаляє
безповоротно, оминаючи Кошик: там помилку виправити буде нічим.

Запобіжники всередині — білий список шляхів, список недоторканних, повторна
перевірка перед видаленням, Кошик замість стирання — знижують ризик, але не
скасовують його. Резервна копія лишається вашим обов'язком: переконайтеся, що
Time Machine чи інший бекап справді працює, перш ніж чистити диск.

## Збирання

```bash
./make.sh test    # прогнати тести
./make.sh build   # зібрати застосунок
./make.sh run     # зібрати й запустити
./make.sh loc     # звірити каталоги рядків із кодом
```

Іконку створює скрипт: `swift tools/make-icon.swift` перемальовує всі PNG у
`Cleaner/Resources/Assets.xcassets`. Правиться код, а не картинка.

`make.sh` завжди спершу викликає `tuist generate`. Це не перестраховка: Tuist
фіксує перелік файлів у момент генерації, тож без цього кроку новий `.swift`
мовчки не потрапить до збірки — і тести тоді «проходять», просто не існуючи.

## Будова

```
CleanerKit/       логіка: PathGuard, Catalog, DiskScanner, Remover, симулятори
CleanerKitTests/
Cleaner/          застосунок на SwiftUI та його ресурси
tools/            генератор іконки, перевірка локалізації
legacy/           попередник — консольна утиліта maccleaner.sh
```

`CleanerKit` не імпортує SwiftUI, а застосунок не працює з файловою системою
напряму. Логіка перевіряється тестами без запуску вікна.

## Локалізація

Дві мови: англійська (мова оригіналу) та українська. Рядки лежать у каталогах —
`Cleaner/Resources/Localizable.xcstrings` для інтерфейсу та
`CleanerKit/Resources/Localizable.xcstrings` для назв категорій і текстів
помилок, якими володіє фреймворк.

Лічильники винесено в окремі рядки рівно з одним числовим аргументом
(`%lld items`, `%lld days`, `%lld devices`): українській потрібні форми
one/few/many, а правило множини може спиратися лише на одне число.

`./make.sh loc` звіряє обидва каталоги з ключами, які насправді видає
компілятор. Це важливіше, ніж здається: Swift будує ключ з інтерполяції, тож
`Text("Selected \(a) · \(b)")` дає `Selected %@ · %@`, а не
`Selected %1$@ · %2$@`. Написаний вручну запис, що не вгадав форму, не збігається
ніколи й провалюється тихо — застосунок просто показує англійську.

## Меню-бар

Застосунок живе ще й у меню-барі. Панель там показує, що назбиралося по кожній
категорії, дає позначити потрібні й видаляє їх після підтвердження, показаного
в самій панелі.

Це підтвердження — свідоме рішення. Відправляти по нього до основного вікна
означало б знищити сенс прибирання з меню-бару, а обійтися без нього — зламати
правило, на якому тримається решта застосунку. Тому панель питає на місці.

**«Працювати лише у фоні»** прибирає іконку з Dock і лишає застосунок у строці
меню. `WindowGroup` створює вікно при старті незалежно від налаштувань, тож у
фоновому режимі `AppDelegate` закриває це стартове вікно й перемикає політику
активації, доки воно не встигло з'явитися, — інакше «лише меню-бар» усе одно
починався б із вікна на екрані.

Закриття вікна не завершує застосунок: пункт у меню-барі лишається, а завершення
— окремий вибір у панелі.

## Модель безпеки

Пріоритет — збереженість даних, а не повнота прибирання.

**Лише Кошик.** Видалення йде через `FileManager.trashItem`, тож штатна кнопка
«Повернути» у Finder працює. Безповоротного видалення в застосунку немає взагалі.

**Білий список, а не чорний.** `PathGuard` пропускає шлях, лише якщо він
абсолютний, не символічне посилання, без `..`, лежить строго всередині
дозволеного кореня і не збігається із самим коренем. Дозволені корені — рівно
корені категорій, тож видаляється тільки їхній вміст.

**Список недоторканних понад білим списком,** порівняння в обидва боки: не можна
ані видалити заборонене, ані видалити теку, всередині якої заборонене лежить.
Знести `Xcode/` не вийде, бо там `Archives`. У списку: `Documents`, `Desktop`,
`Downloads`, iCloud Drive, Photos, Mail, Messages, Keychains, `~/.ssh`, резервні
копії пристроїв, `Xcode/Archives`, `Xcode/UserData`.

Порівняння йде за компонентами шляху, а не за рядком: рядковий префікс вважав би
`CachesOther` продовженням `Caches`.

**Повторна перевірка перед видаленням.** `Remover` не довіряє результатам
сканування й проганяє кожен шлях через `PathGuard` заново безпосередньо перед
переміщенням: між скануванням і натисканням кнопки минають хвилини.

**Нічого не позначено за замовчуванням.** Збій на одному шляху не спиняє решту —
звіт збирається поелементно.

## Файли

Вкладка «Файли» — оборотне прибирання, усе їде до Кошика.

Категорія розкривається у список конкретних знахідок: ім'я, розмір, дата зміни.
Позначити можна будь-що — окремий файл, групу чи категорію цілком. Галочка
категорії показує проміжний стан, коли всередині вибрано не все, і натискання по
ній добирає решту.

Категорії з кількома коренями показують спершу групи: у «Кешах пакетних
менеджерів» ім'я `content-v2` саме собою нічого не каже, а під заголовком
`.npm/_cacache` — каже.

| Категорія | Що це | Наслідок |
|---|---|---|
| Xcode DerivedData | Індекси та проміжні збірки | Перша збірка довша |
| Символи пристроїв | `iOS/watchOS/tvOS DeviceSupport` | Завантажиться при під'єднанні пристрою |
| Кеші пакетних менеджерів | npm, Yarn, pnpm, pip, CocoaPods, Gradle | Перше встановлення довше |
| Робочі теки XcodeBuildMCP | Робочі копії збірок через MCP | Створяться заново |
| Кеш SwiftPM і документації | `org.swift.swiftpm`, `DocumentationCache` | Завантажиться знову |
| Кеші програм | Xcode, JetBrains, VS Code, Chrome, Homebrew, playwright та інші | Програми перебудують кеш |
| Завантажені оновлення | Теки `*.ShipIt` у `~/Library/Caches` | За потреби завантажаться знову |

Перелік `*.ShipIt` обчислюється за фактичним вмістом теки, а не заданий
константою: набір програм у кожного свій.

## Симулятори

Вкладку «Симулятори» винесено окремо **тому, що тут видалення безповоротне**.
Тека симулятора прив'язана до бази CoreSimulator, тож перенести її до Кошика не
можна — база розсинхронізується. Видаляє `simctl`, повз Кошик.

Звідси й інші правила в цьому розділі:

- **«Позначити невживані»** позначає те, що завідомо мертве: пристрої без
  встановленого runtime і runtime, якими не користується жоден пристрій.
- Запущений симулятор видалити не можна — спершу завершіть його.
- Runtime із позначкою `Deletable: NO` захищений системою.
- Підтвердження вимагає окремо позначити «Розумію, що це не потрапить до
  Кошика» — звичайного натискання замало.

Розбір виводу `simctl` перевіряється на записаних фікстурах, зокрема на іменах
із дужками на кшталт `iPad Pro 13-inch (M5)`: розбір за дужками вважав би UDID'ом
рядок `M5`.

## Пісочниця

App Sandbox вимкнено свідомо: у пісочниці `~/Library/Developer` недоступний без
того, щоб користувач обирав кожну теку вручну. Це локальний інструмент, не для
App Store.
