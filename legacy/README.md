# maccleaner

Простая CLI-утилита для чистки мусора разработчика на macOS. Один файл, только
системные средства — никаких зависимостей.

## Быстрый старт

```bash
./maccleaner.sh                 # посмотреть, что можно освободить (ничего не удаляет)
./maccleaner.sh --apply         # почистить обратимо — всё уезжает в Корзину
```

## Модель безопасности

Главный приоритет — не потерять данные. Четыре независимых уровня:

1. **Dry-run по умолчанию.** Без `--apply` утилита только считает и печатает.
2. **Обратимость.** `--apply` не удаляет, а перемещает найденное в
   `~/.Trash/maccleaner-<timestamp>/`. Проверили, что всё собирается — очистили
   Корзину. Безвозвратное стирание — только явным `--apply --purge`, и оно
   требует ввести слово `PURGE` вручную.
3. **Whitelist, а не blacklist.** Каждый путь проходит через `guard()`, который
   пропускает его только если путь: абсолютный, не симлинк, без `..`, лежит
   **строго внутри** одного из разрешённых корней, не совпадает с самим корнем и
   не пересекается со стоп-листом. Всё остальное отклоняется.
4. **Стоп-лист поверх whitelist.** Никогда не трогаются `Documents`, `Desktop`,
   `Downloads`, iCloud Drive (`Mobile Documents`), Photos, Mail, Messages,
   Keychains, `~/.ssh`, бэкапы устройств (`MobileSync`), **Xcode Archives**
   (там лежат собранные релизы) и **Xcode UserData** (схемы, сниппеты,
   брейкпоинты).

Также: удаляется всегда *содержимое* каталога, а не сам каталог; нигде нет
`rm -rf $VAR` без предварительной проверки; каждое действие пишется в
`~/Library/Logs/maccleaner-<timestamp>.log`.

Проверить защиту можно в любой момент:

```bash
./maccleaner.sh --self-test
```

## Задачи

| Задача | Что чистит | Последствие |
|---|---|---|
| `report` | ничего — только отчёт по крупнейшим каталогам | — |
| `derived` | `Xcode/DerivedData` | первая сборка дольше, переиндексация |
| `devicesupport` | `iOS/watchOS/tvOS DeviceSupport` | перекачается при подключении устройства |
| `simulators` | кэши CoreSimulator + `simctl delete unavailable` | удаляются симуляторы уже недоступных runtime'ов |
| `xcodebuildmcp` | `XcodeBuildMCP/workspaces` | пересоздастся |
| `swiftpm` | кэш SwiftPM, DocumentationCache | пакеты перекачаются |
| `pkgcaches` | npm, yarn, pnpm, pip, CocoaPods, Gradle, playwright, puppeteer | первая установка дольше |
| `brew` | `brew cleanup --prune=all` | старые версии формул |
| `appcaches` | известные кэши в `~/Library/Caches` (Xcode, VSCode, JetBrains, Chrome, Slack…) | приложения перестроят кэш |
| `logs` | файлы в `~/Library/Logs` старше 30 дней | — |
| `simdevices` | **интерактивно**: симуляторы по выбору | необратимо, см. ниже |
| `simruntimes` | **интерактивно**: runtime-образы iOS по выбору | необратимо, качается заново |

Выборочно:

```bash
./maccleaner.sh --only derived,devicesupport,simulators --apply
```

## Интерактивный выбор симуляторов

CoreSimulator — обычно самая крупная статья на диске, но что именно там лишнее,
автоматика решать не должна. Поэтому две задачи работают через список с выбором.

```bash
./maccleaner.sh --only simdevices            # только посмотреть
./maccleaner.sh --only simdevices --apply    # выбрать номера и удалить
```

Таблица отсортирована по размеру, крупные сверху:

```
  №      размер  изменён      устройство                   runtime        состояние
  ──────────────────────────────────────────────────────────────────────────────────
  1     13.7 GB  2026-08-11  iPhone 17 Pro                iOS 26.4       Booted ← запущен
  2      4.9 GB  2026-08-10  iPhone 17                    iOS 26.2       недоступен ← runtime не установлен
  3      4.0 GB  2026-08-17  iPhone 17 Pro                iOS 26.5       Shutdown
  ...
```

Ввод номеров: `3` · `1,4,7` · `2-9` · `all`. Пустая строка — не удалять ничего.
Мусор и номера вне диапазона отбрасываются с предупреждением.

Аналогично для runtime-образов (`/Library/Developer/CoreSimulator`, часто
100+ GB) — там же видно размер, дату последнего использования, флаг `Deletable`
и сколько симуляторов привязано к каждому образу:

```bash
./maccleaner.sh --only simruntimes --apply
```

### Почему здесь безопасность устроена иначе

Симуляторы удаляются через `simctl`, а не перемещением в Корзину: `mv` каталога
устройства оставил бы рассинхронизированной базу CoreSimulator. Значит, операция
**необратима** — и защита строится на другом:

- Ничего не выбрано по умолчанию: вы указываете номера руками.
- Перед удалением печатается итоговый список с размерами.
- Подтверждение — ввод слова `DELETE`, а не `y`.
- **Запущенный симулятор пропускается** — сначала его надо завершить.
- Задачи не работают в неинтерактивном режиме (пайп, cron) и **игнорируют
  `--yes`**: массовое удаление симуляторов «не спрашивая» не выполняется никогда.
- В dry-run задачи только показывают список.

Само устройство Xcode пересоздаёт за секунды, но установленные в нём приложения
и их данные пропадут. Runtime-образ возвращается загрузкой в Xcode (несколько ГБ).

## Опции

```
(без опций)     dry-run
--apply         выполнить (в Корзину)
--purge         с --apply: стирать сразу, необратимо
--only LIST     только указанные задачи, через запятую
--yes / -y      без подтверждения
--verbose / -v  показывать и пустые пункты
--self-test     проверить защиту guard() (21 проверка)
--list          список задач
--help          справка
```

## Замечания

- Перед чисткой `derived` лучше закрыть Xcode — утилита предупредит, если он запущен.
- `devicesupport` обычно самая крупная статья (5–6 GB на версию iOS), но файлы
  перекачиваются с устройства автоматически.
- Утилита работает только в домашнем каталоге и никогда не просит `sudo`.
